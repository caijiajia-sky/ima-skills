# AI-Skill 外部知识蒸馏更新工作流

> 本Skill帮助用户对IMA平台技能进行外部知识蒸馏和更新迭代，支持与已注册技能形成联动组合技。

---

## 适用场景

- ✅ 对已有技能进行外部知识蒸馏更新
- ✅ 将工作流笔记蒸馏成可安装的Skill
- ✅ 技能版本迭代（1.1.2→1.2.0）
- ✅ 与盘古技能(huadu-pangu)形成联动
- ❌ 不适用于纯数据型技能（如价格表、产品目录）
- ❌ 不适用于需要频繁更新的实时数据

---

## 核心依赖

本Skill依赖以下已注册技能：

| 技能名称 | Skill ID | 作用 |
|---------|----------|------|
| **huadu-pangu** (盘古技能) | 7465846335109135 | 信息蒸馏核心能力 |
| **bocha-search** | - | 博查AI搜索引擎，多源聚合搜索 |
| **minimax-token-plan** | - | MiniMax极速版API搜索，深度内容理解 |
| **search (source="web")** | - | 基础联网搜索工具，全网覆盖 |

> 💡 **三网合一搜索策略**：本Skill在执行散发性搜索时，必须同时调用**全部三个联网搜索技能**，形成互补覆盖：
> - **bocha-search**：提供高质量AI搜索结果，适合快速定位权威来源
> - **minimax-token-plan**：提供深度搜索和图片理解能力，适合复杂查询
> - **search (source="web")**：提供全网广度覆盖，确保不遗漏任何相关信息

## 执行流程（7步）

### Step 1: 加载技能并理解作用

**执行内容**：
```python
use_skill(name="目标技能名称")
```

- 读取 SKILL.md 了解技能简介、功能特性、核心流程
- 读取 references/workflow.md 了解详细执行流程
- 读取 references/ 下的其他辅助文档

**产出物**：
- 技能的核心功能理解
- 触发规则和数据来源规范
- 执行流程的关键节点

### Step 2: 对抗性验证技能

**执行内容**：
1. 检查技能文件的完整性（SKILL.md、scripts/、references/）
2. 验证核心脚本是否存在且可执行
3. 检查版本号和更新日志
4. 识别技能的潜在问题点和边界

**验证维度**：

| 维度 | 检查内容 | 预期结果 |
|------|----------|----------|
| 文件完整性 | SKILL.md、workflow.md、脚本 | ✅ 存在 |
| 版本信息 | version字段 | 明确的版本号 |
| 更新日志 | updated字段 | 完整的更新历史 |
| 依赖项 | scripts/、references/ | 完整 |
| 功能边界 | 强制规则、禁止项 | 清晰 |

**产出物**：
- 技能现状评估报告
- 待改进问题点清单

### Step 3: 散发性联想 + 联网搜索（三网合一）

**⚠️ 强制要求**：必须同时调用**全部三个联网搜索技能**，缺一不可！

**⚠️ 执行验证要求**：
- **禁止仅修改文档** - 必须真正执行搜索工作流
- **禁止仅验证文档** - 必须验证搜索是否真正执行
- **禁止仅检查定义** - 必须检查产出物是否存在

**执行验证检查点**：
| 检查项 | 验证方法 | 判定标准 |
|--------|----------|----------|
| 三网搜索执行 | 检查搜索结果文件是否存在 | 每网至少1次搜索结果 |
| 知识库搜索执行 | 检查kb搜索结果 | 至少3条kb检索结果 |
| 原文获取执行 | 检查fetch调用记录 | 至少5篇原文被fetch |
| 产出物存在 | 检查workspace输出文件 | 搜索结果、原文内容文件存在 |

**执行策略**：
围绕技能主题进行多维度搜索，每个维度至少获取3-5篇相关文章原文。
搜索时需将关键词分解为**最小颗粒度元素/实体**，对每个元素进行独立搜索。

#### 3.1 最小颗粒度元素解析

**执行步骤**：
1. 将搜索主题拆解为**原子级实体**（不可再分的基本概念）
2. 对每个原子实体，列出其**属性、关系、行为、约束**四个维度
3. 对每个维度生成3-5个独立搜索关键词

**解析模板**：
```
原始主题 → 原子实体 → 四维分解
                              ├─ 属性维度：...
                              ├─ 关系维度：...
                              ├─ 行为维度：...
                              └─ 约束维度：...
```

**示例**（以"公众号封面设计"为例）：
```
主题：公众号封面设计
├─ 原子实体1：封面图
│   ├─ 属性：尺寸、格式、分辨率、文件大小
│   ├─ 关系：与文章内容、与读者群体
│   ├─ 行为：点击率、分享率、停留时长
│   └─ 约束：平台规则、加载速度
├─ 原子实体2：色彩
│   ├─ 属性：色相、饱和度、亮度
│   ├─ 关系：与品牌、与情绪
│   ├─ 行为：吸引注意、传达情感
│   └─ 约束：色盲友好、品牌一致性
└─ 原子实体3：构图
    ├─ 属性：黄金比例、三分法、对角线
    ├─ 关系：与主体、与留白
    ├─ 行为：引导视线、创造焦点
    └─ 约束：平衡感、层次感
```

#### 3.2 三网合一搜索执行

**必须同时执行以下三种搜索方式**：

##### A. bocha-search（博查AI搜索）

**调用方式**：
```bash
python3 /sandbox/workspace/skills/bocha-search/scripts/bocha_search.py "搜索关键词" 10
```

**执行规范**：
- 每个原子实体的每个维度至少执行1次搜索
- 可通过 `--freshness` 参数限定时间范围
- 返回15条高质量AI搜索结果

**搜索示例**：
```bash
# 基础规范搜索
python3 /sandbox/workspace/skills/bocha-search/scripts/bocha_search.py "公众号封面设计技巧 爆款文章 高点击率" 10

# 尺寸规范搜索
python3 /sandbox/workspace/skills/bocha-search/scripts/bocha_search.py "微信公众号封面图尺寸比例 最佳实践 2.35:1" 10

# AI生图提示词搜索
python3 /sandbox/workspace/skills/bocha-search/scripts/bocha_search.py "AI生成封面图提示词技巧 prompt engineering" 10
```

##### B. minimax-token-plan（MiniMax极速版搜索）

**调用方式**：
```javascript
minimax_web_search({
  query: "搜索关键词"
})
```

**执行规范**：
- 使用3-5个关键词组合，效果最佳
- 对于时效性话题，加入当前日期关键词
- 返回有机搜索结果和相关搜索建议

**搜索示例**：
```javascript

#### 3.4 知识库全覆盖搜索

**⚠️ 强制要求**：在执行联网搜索前，必须先对知识库进行全面搜索！

1. 对每个原子实体在**全部知识库**中进行检索

3. 对检索到的内容使用 `fetch` 获取原文

# 对每个原子实体搜索所有知识库
for entity in atomic_entities:
    for dimension in dimensions:
        search(question=f"{entity} {dimension}", source="kb")
        
# 对检索到的内容获取原文
fetch(id="media_id/note_id", question="提取完整内容", type="media_id/note_id")
```

**知识库搜索关键词示例**：

### 框架3：散发性搜索框架（三网合一）

**一句话描述**：围绕主题进行多维度联网搜索，同时调用全部三个联网搜索技能获取外部知识

**来源证据**：
- explosive-cover-generator-gzh案例：8个搜索维度
- bocha-search技能
- minimax-token-plan技能
- search(source="web")工具

**应用方式**：
1. **最小颗粒度解析**：将主题拆解为原子级实体，对每个实体进行四维分解（属性、关系、行为、约束）
2. **三网并行搜索**：对每个维度同时执行三种搜索
   - bocha-search：高质量AI搜索结果
   - minimax-token-plan：深度搜索和内容理解
   - search(web)：全网广度覆盖

## 附录A：MUSE-Autoskill 五阶段技能生命周期

> **来源**：MUSE-Autoskill: Self-Evolving Agents via Skill Creation, Memory, Management, and Evaluation（字节跳动）

### 核心设计理念

将技能视为拥有完整**生命周期**的资产，而非一次性生成产物。五个模块围绕技能库协同工作，构成技能从创建到复用、从验证到进化的完整闭环。

### 五阶段范式

| 阶段 | 名称 | 核心职责 | 关键产出 |
|:---:|------|---------|---------|
| 1 | **技能创建** | 当现有技能无法满足任务需求时，生成功能规格说明 | 接口定义、可执行脚本、单元测试 |
| 2 | **技能评估** | 执行技能自带的单元测试 | 通过/失败信号 |
| 3 | **技能精炼** | 分析错误信息并自动修复代码 | 修复后重新评估 |
| 4 | **技能记忆** | 每次调用后将经验追加写入独立记忆文件 | 跨任务经验积累 |
| 5 | **技能管理** | 两阶段检索策略管理技能库 | 渐进式披露机制 |

### 技能级记忆设计

```markdown
每个技能附带独立记忆文件：
├── 技能记忆/
│   ├── skill_xxx.md          # 跨任务积累的经验
│   └── skill_xxx_tests.md    # 单元测试
```

**记忆内容**：执行经验、注意事项、失败模式

**多层次记忆体系**：
- 短期记忆：当前任务的推理上下文
- 技能记忆：跨会话的技能级经验
- 长期记忆：跨任务的通用经验

### 两阶段检索策略

| 阶段 | 内容 | 开销 |
|------|------|------|
| 第一阶段 | 仅注入技能"名称"+"一句话描述" | 低（线性增长） |
| 第二阶段 | Agent筛选后加载完整接口定义 | 按需加载 |

### 自适应上下文压缩

- 固定保留前5轮与后5轮
- 中间部分进入压缩流程
- 原始节点通过不可变指针完整保留

## 附录B：华为云三段式Skill自进化机制

> **来源**：让Skill从执行中生长——Cloud Agent Harness的三段式Skill自进化机制（华为云）

### 核心问题

传统靠人工编写和维护Skill很快会遇到瓶颈：
- 业务场景变化比文档更新快
- 操作者发现的技巧很难被系统化沉淀
- 大量有价值但低频的操作经验最终流失

### 三种技术流派

| 流派 | 核心思想 | 优点 | 缺点 |
|------|---------|------|------|
| **轨迹蒸馏** | 从历史轨迹中自动沉淀Skill | 数据效率高、可解释 | 依赖已有轨迹覆盖度 |
| **进化迭代** | 变异—评估—选择迭代 | 探索能力强、可自我提升 | 计算成本高、安全性不足 |
| **评估驱动** | 测试用例驱动的工程优化 | 质量可控、企业友好 | 自主性有限、想象力受限 |

### 三段式自进化机制

#### 第一阶段：任务反思

**触发条件**：任务复杂度或用户干预超过阈值

**产出**：执行日志中的成功步骤、分支判断、异常修复被提炼为结构化Skill文档

**关键设计**：
- 补丁机制：精准修改Skill中对应段落，不全文重写
- 只保留使任务成功所必需的步骤，丢弃试错分支

#### 第二阶段：进化筛选

**选取原则**：
1. 失败率偏高的Skill优先
2. 长期未调用但仍有订阅者的Skill次之
3. 表现稳定的Skill排在最后

**变异阶段**：
- 输入：该Skill近期所有执行的失败日志
- 输出：针对每个失败模式的修改方案

**筛选阶段**：所有变异体进入评估管道接受质量检定

#### 第三阶段：评估管道

| 层级 | 检查内容 | 作用 |
|------|---------|------|
| 准入检查 | 格式校验、安全扫描、最小功能测试 | 确保Skill可加载和执行 |
| 效果评估 | 沙箱环境中运行完整测试用例 | 记录准确率、延迟、Token消耗 |
| 目标筛选 | 对比变异体与原始Skill差异 | 保留综合最优或特定维度显著优势的变体 |

**多样性与安全**：
- 允许在特定维度有显著优势的变体同时存在
- 可配置人工审核进化后的Skill

## 附录C：EvoSkills 共同进化框架

> **来源**：EvoSkills: Self-Evolving Agent Skills via Co-Evolutionary Verification（arXiv:2604.01687）

### 核心问题

三个层层递进的问题：
1. 人写的技能，AI未必买账（人机认知错位）
2. 现有自进化方法存在"工具-技能"鸿沟
3. 多文件技能包一次性生成天然不可靠

### 核心思想：共同进化

两个组件交替优化：
- **技能生成器**：维护对话上下文，积累反馈，逐步迭代改进
- **代理验证器**：运行在独立LLM会话中，自动生成测试用例和诊断

### 关键发现

| 发现 | 结论 |
|------|------|
| 智能体能创造比人类更好的技能 | 编码自身的推理模式和工具使用偏好 |
| 技能可跨模型家族迁移 | 编码的是可复用任务结构 |
| 人机认知错位是真实存在的 | 某些领域人类编写技能反而降低性能 |

### 实验结果

- EvoSkills达到 **71.1%** 通过率
- 比无技能基线高 **+40.5pp**
- 比人类编写技能高 **+17.6pp**
- 在5轮迭代内超越人类编写的技能

### 共同进化循环

```
技能生成器 ──→ 代理验证器
    ↑                  │
    │                  ↓
    └── 迭代改进 ◄────┘
```

**驱动机制**：
- 代理测试发现问题 → 驱动技能修复
- 代理测试通过但真实测试失败 → 驱动测试升级

## 附录D：五步框架——Workflow转可进化Skill

> **来源**：你可能不再需要workflow——五步框架把Workflow变成可进化的Skill（宝玉）

### 核心观点

**大部分workflow编排场景，都可以被Agent + Skills取代。**

Skill应该被看作可组合的模块，用自然语言描述协作关系，实现用自然语言去编排工作流。

### 五步框架

#### 第一步：拆分

把工作流拆成单一职责的skill或subagent，每个模块只做一件事。

```markdown
示例：写作工作流
├── article-analyzer：分析素材
├── outliner：生成提纲
├── writer-agent：根据提纲写草稿
└── polish：润色定稿
```

#### 第二步：编排

在主skill里用自然语言描述整个流程。

```markdown
示例编排逻辑：
"先调用article-analyzer分析素材，分析完成后保存analysis.md，
然后根据分析结果生成2-3个不同风格的提纲方案，
为每个方案并行启动writer-agent写草稿。"
```

**优势**：条件分支、并行执行、错误处理都可用自然语言描述

#### 第三步：存储

所有中间结果都保存成本地文件。

**三个好处**：
- 可追溯：出问题了能看到每一步的输出
- 可断点续传：中途停了，下次从上次位置继续
- 可人工干预：不满意某一步结果，手动改完让Agent继续

```markdown
文件结构示例：
source.md → analysis.md → outline-a.md → draft-outline-a.md → final.md
```

#### 第四步：分摊

**Subagent之间只传文件路径，不传内容。**

**好处**：
- 上下文窗口干净（只传路径，subagent自己读取）
- 可以并行启动多个subagent（互不干扰）

```markdown
writer-agent启动参数：
├── source文件路径
├── analysis文件路径
└── outline文件路径
```

#### 第五步：迭代

这是Agent + Skills相比传统workflow最大的优势：**可以持续进化**。

**迭代方式**：
- 发现某个skill的提示词不够好？让AI帮你改
- 某个流程步骤可以优化？随时调整
- subagent可以自我迭代system prompt

**演进原则**：skills会越用越好，而不是搭完就放在那儿吃灰

### 边界场景

| 适用Agent+Skills | 适用Workflow |
|-----------------|-------------|
| 输入多变、需要判断的任务 | 严格审计要求的合规流程 |
| 跨系统协调的复杂流程 | 超高频执行的简单任务 |
| 需要频繁迭代的工作流 | 非技术用户的可视化需求 |
| 需要分享复用的自动化逻辑 | |

### 混合架构建议

**确定性逻辑用脚本，AI判断用Agent**：

```markdown
polish skill执行完润色后，自动调用format-markdown.ts脚本处理格式：
├── 脚本：处理格式规则（中文引号、全角半角等）
└── Agent：处理需要判断的任务
```

### 这个Skill不能做什么
- 不能替代人工判断所有决策
- 不能保证识别所有设计错误
- 不适用于纯数据型技能（如价格表、产品目录）
- 不适用于需要频繁更新的实时数据
