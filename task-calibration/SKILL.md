# 任务校准

## 概述

在执行非平凡任务前，先走一轮结构化审查，把模糊需求变成可执行的任务定义。核心解决的问题是：需求没对齐就开干，导致交付物不符合预期。

## 触发判断

收到用户任务时，先判断是否需要校准：

- **需要校准**：任务涉及 2 个及以上步骤，或产出物会被直接使用（交付给他人、用于决策、贴到文档里），或用户只给了模糊方向
- **直接执行**：简单问答、格式转换、单步操作、纯信息查询

如果判断不需要校准，跳过本技能，直接执行。

## 你的工作方式

```
1. 需求拆解 → 把自然语言请求拆成结构化要素
2. 五问审查 → 对拆解结果做压力测试
3. 追问对齐 → 信息不足时列出追问清单，等用户确认
4. 任务摘要 → 对齐完成后输出结构化摘要，持久化到 memory
5. 执行 → 按对齐后的定义执行
```

## Phase 1：需求拆解

把用户的自然语言请求拆成以下要素，缺失的标注为"未明确"：

| 要素 | 说明 |
|------|------|
| 目标 | 一句话说清楚要达成什么 |
| 约束 | 时间、格式、篇幅、技术栈等硬限制 |
| 隐含假设 | 用户没说但你推断出的前提条件 |
| 验收标准 | 交付物满足什么条件算"做完了" |
| 上下文 | 用户身份、使用场景、受众是谁 |

**为什么这么做**：用户说"帮我写个方案"，可能要的是给老板看的一页纸，也可能是给技术团队看的二十页文档。不拆开就开干，做出来的大概率不是用户要的。

## Phase 2：五问审查

对拆解结果逐条过检：

1. **目标清楚吗？** ——含糊的地方在哪？"提升用户体验"这种目标就是含糊的，"将注册转化率从 30% 提升到 45%"才是清楚的
2. **最可能在哪里失败？** ——这个任务最大的风险点在哪？是技术可行性、数据不足、还是需求本身矛盾？
3. **忽略了什么？** ——用户没提到的但做这件事必须考虑的因素
4. **哪些假设需要验证？** ——隐含假设中哪些可能是错的？如果错了方向会怎样？
5. **有没有更简单/更便宜/更稳妥的替代方案？** ——用户要的方案是不是过度工程了？有没有 MVP 可以先验证？

如果五个问题都能直接回答且无风险，简要说明后进入 Phase 4。如果任一问题暴露出信息缺口，进入 Phase 3。

## Phase 3：追问对齐

信息不足时，**不要急着执行**。把需要确认的问题整理成清单，一次性发给用户：

```markdown
### 需要对齐以下问题

1. [具体问题1]
2. [具体问题2]
3. [具体问题3]

请确认或补充，确认后我开始执行。
```

**追问原则**：
- 只问真正影响执行方向的问题，不问锦上添花的
- 给出你的默认建议，让用户可以简单回复"按默认来"
- 一次问完，不要挤牙膏式追问

## Phase 4：任务摘要

对齐完成后，输出结构化摘要：

```markdown
### 任务摘要

- **目标**：[一句话]
- **约束**：[列出]
- **已识别风险**：[列出]
- **验收标准**：[列出]
- **待确认项**：[无 / 列出]
```

将摘要写入 `memory_md`，确保跨会话可召回，下次对话不用重复说明背景。

## Phase 5：执行

按对齐后的任务定义执行。执行中如果发现新的信息导致任务定义需要调整，先停下来告知用户，不要自行更改方向。

## 工作流示例

### 示例 1：模糊需求

**用户**："帮我做个竞品分析"

**Phase 1 拆解**：
- 目标：未明确——是了解市场格局？找差异化机会？评估某个竞品的威胁？
- 约束：未明确——分析深度、竞品范围、时间范围
- 隐含假设：用户在做一个产品决策，需要竞品信息支撑
- 验收标准：未明确
- 上下文：未明确

**Phase 2 审查**：目标含糊，直接进入 Phase 3

**Phase 3 追问**：
1. 竞品分析的目的是什么？（找差异化机会 / 评估威胁 / 了解市场格局）
2. 分析哪几个竞品？还是需要我来选？
3. 产出用什么格式？（表格对比 / 文档报告 / PPT 大纲）
4. 默认建议：分析 3-5 个头部竞品，产出表格+要点摘要，按默认来可以吗？

### 示例 2：需求相对清楚

**用户**："帮我把这份会议纪要整理成给老板的周报，一页纸以内，突出进度和风险"

**Phase 1 拆解**：
- 目标：会议纪要转一页纸周报
- 约束：一页纸、受众是老板、突出进度和风险
- 隐含假设：会议纪要内容足够支撑周报
- 验收标准：一页纸、包含进度和风险、老板能快速看懂
- 上下文：老板、周报场景

**Phase 2 审查**：目标清楚，约束明确，风险低。简要说明后直接进入 Phase 4 输出摘要，然后执行。
